# Motion-model reference experiment

This directory contains a dependency-free Python research harness for the
motion-model questions in [the experiment plan](../../docs/MOTION_MODEL_EXPERIMENT_PLAN.md).
It is deliberately outside the .NET library and is **not** production physics,
a runtime API, or evidence that the historical Workshop equation has been
recovered.

## Run it

Requires Python 3.10 or newer; no third-party packages are needed.

From the repository root:

```bash
python tools/motion-lab/motion_experiment.py --output artifacts/motion-experiment.csv
python -m unittest discover -s tools/motion-lab -p "test_*.py" -v
```

The default experiment emits long-form CSV for 16 stable identity seeds across
four variants: linear interpolation, smoothstep easing, spring-damper tracking
with a wider illustrative “green” parameter range, and spring-damper tracking
with a narrower illustrative “veteran” range. The target follows a smoothstep
from 0 to 1 over 0.5 seconds and then holds. The default duration is 1.5 seconds
at a fixed 1/240-second step.

CSV columns include the model/profile, identity seed, time, target, position,
velocity, acceleration, tracking error, natural frequency, and damping ratio.
Use the output to calculate overshoot, peak velocity/acceleration, settling
time, and population variance rather than relying only on a visual impression.

## What the harness means mathematically

For each dynamic identity it samples a fixed natural frequency \(\omega_n\)
and damping ratio \(\zeta\) once, then derives:

\[
k=m\omega_n^2, \qquad c=2\zeta m\omega_n
\]

The scalar system uses target-relative damping:

\[
m\ddot{x}=k(r-x)+c(\dot r-\dot x)
\]

It is integrated using semi-implicit Euler at a fixed step. The script uses a
small SplitMix64-based sampler so the identity samples do not depend on the
Python standard library's random-number generator implementation.

The example ranges are **experimental placeholders**, not measured human
biomechanics, approved gameplay tuning, or a claim that experience should
change every parameter. “Green” uses \(\omega_n\in[7,11]\) and
\(\zeta\in[0.55,1.25]\); “veteran” uses \(\omega_n\in[8.6,9.4]\) and
\(\zeta\in[0.88,1.04]\). The model keeps mass fixed at 1 because changing
mass while deriving both \(k\) and \(c\) from \(\omega_n\) and \(\zeta\)
does not change the ideal normalized response. Mass becomes behaviorally
distinct if other forces, constraints, or parameter mappings do not scale with it.

## Limitations that are intentional

- This is a one-dimensional scalar teaching model, not articulated-body physics.
- It has no gravity, contact, joint limits, muscle actuation, IK, or collision handling.
- The kinematic linear baseline is compared against a smoothstep target; its
  difference from that target is intentional and recorded as tracking error.
- Semi-implicit Euler has timestep-dependent error. Repeat the run at smaller
  steps and compare results before drawing conclusions.
- The profile bounds are a hypothesis to test, not a skill system contract.
- The output is not generated by the current Gestures .NET evaluator.

The purpose is to make the next discussion empirical: inspect the response,
quantify the trade-offs, vary one assumption at a time, and only then decide
which motion-law parameters deserve a durable definition.
