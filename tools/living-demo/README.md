# Living motion scene: three real evaluated transform tracks

This scene is generated by the C# program in this directory. It is not an independently animated SVG sketch.

```powershell
dotnet run --project tools/living-demo/living-demo.csproj --configuration Release -- --output docs/assets/gesture-motion.svg
```

The program uses two real systems:

1. **FSM_API** advances the demonstration through `Ready → Running → Complete`.
2. **TheSingularityWorkshop.Gestures.GestureEvaluator** evaluates one five-keyframe `GestureDefinition` at 49 elapsed-time samples.

The definition contains three named transforms: `root`, `tool`, and `load`. For each sample, the SVG trajectories and animated markers use the corresponding returned `EvaluatedPose.LocalTransforms` values. Each marker's position, heading, and size come from that transform's position, quaternion rotation, and scale. The straight segments reflect the evaluator's linear position interpolation.

**Important boundary:** the evaluator interpolates named transforms independently. This demonstration does not compose a rig hierarchy, resolve parent-child relationships, run IK, detect collisions, or simulate physical forces. The labels `root`, `tool`, and `load` are example data keys, not proof that the evaluator understands a mechanical assembly. Their 2-D positions are projected into a shared diagram for visual comparison.

The browser plays serialized samples; it does not execute C# or call FSM_API at display time. The build workflow regenerates and validates the SVG and checks that the committed asset matches the C# output. Reduced-motion preferences are respected.

This is deliberately an honest visual of the current evaluator contract. A later motion-model demo should only depict forces, contact, hierarchy, or environmental causality after a real implementation produces and tests those results. Package publication remains disabled.
